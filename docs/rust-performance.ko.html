Rust 전환, 어디까지 좋아졌나

선택형 Rust 코어 채택 권장

판정과 적용 범위

다수 문자열 치환 지연 -27.3%, CPU -26.3%, 개별 자식 peak RSS +0.4%. 메모리 절감은 입증되지 않았습니다.

문자열 치환 코어만 Rust로 옮겼습니다. 탐지·정책·PII·호스트 처리는 셸입니다. 기본 실행은 셸/jq이며 Rust 부재·실패 시 기존 경로로 복귀합니다. 플랫폼별 사전 빌드 배포와 기본값 전환은 후속 과제입니다.

사전 기준: 목표 경로 지연 또는 CPU 10% 이상 개선, 일반 경로 지연 5% 초과 회귀는 추가 검증. 회귀 항목: 없음.

실제 CLI · 시나리오별 비교

최적화된 셸=100%. 낮을수록 좋습니다. 매 호출 전체 기대값을 검사하며 CPU는 user+system 시간입니다. 정상 경로의 차이는 Rust 효과로 보지 않습니다.

코어 자체의 효과

15회 교대 측정. 프로세스 시작·JSON 입출력 포함, 스캐너·전체 파이프라인 제외. 이 배수를 CLI 배수로 읽으면 안 됩니다.

동시 부하와 프로세스 메모리

보존된 초기 실험은 rootless Docker cgroup driver none으로 컨테이너별 제한이 적용되지 않았습니다. 현재 결과의 cgroup 격리 여부와 실제 CPU·메모리 한도는 아래 원시 환경 값으로 확인합니다. worker 1/4, 새 컨테이너에서 3회 교대 반복. 10 ms 표본 RSS 합은 드라이버·init 포함, 공유 페이지 중복·순간 peak 누락 가능성이 있습니다. 페이지 캐시·daemon·빌드는 제외합니다. cgroup peak를 컨테이너 메모리로 해석하지 않습니다.

기본 셸 경로의 비용과 측정 한계

정상 입력 재측정 21쌍: -0.8% (95% 기술 구간 -1.6 ~ +0.5%). Rust를 호출하지 않는 정상 경로의 차이는 코어 효과가 아닙니다.

동일 반복 번호를 짝지은 bootstrap 2,000회, CPython Random(60261104)와 같은 추출. p95나 공유 머신의 장기 변동 보장이 아닙니다. 과거 Python 측정 코어 RSS에는 fork/exec 전 약 11 MiB 바닥값이 있어 메모리 절감 근거로 쓰지 않았습니다. 새 Rust smoke 수치는 이 과거 결과와 합치지 않습니다. 합성 출력, cold readiness cache, PII off 조건이며 실제 모델 응답·원격 PII·전체 저장소 스캔으로 일반화하지 않습니다.
