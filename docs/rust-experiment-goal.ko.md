# agent-guard 성능·구조 개선 목표와 완료 조건

내부 작업 문서. 기존 문서의 번역이 아니다.

## 목표

**마스킹 강도를 유지하면서 agent-guard의 병목을 검증·개선하고, Rust 전환의 실익을 근거로 판정하여 검토 가능한 PR 단위로 저장소에 반영한다.**

기존 셸 최적화 결과와 최적화 이후 Rust 추가 이득을 구분한다. Rust 첫 범위는 `redact_tool_response_json` 문자열 치환이다. 탐지기·정책·호스트 어댑터는 유지한다. 전체 재작성의 이득으로 확대 해석하지 않는다.

## 사전에 정한 판정 기준

- 호환성: 독립 기대값 및 기존 jq와의 차등 검사에서 불일치 0. Unicode, 제어문자, 중복·겹침·연쇄 치환, 순서, 프로토콜 필드, 예산 경계를 포함한다.
- 오류: 잘못된 입력·실행 실패가 원문 유출이나 부분 출력으로 이어지지 않아야 한다. 바이너리 부재 시 정상 셸 경로로 복귀한다.
- 성능: 동일 Docker 이미지·스캐너·CPU/메모리 제한에서 교대 순서 반복 측정. 시작 비용을 포함한 코어와 실제 CLI를 모두 비교한다. 목표 경로 지연 또는 CPU 중앙값 10% 이상 개선, 일반 경로 5% 초과 회귀는 재측정·원인 분석 없이는 채택하지 않는다.
- 자원: CPU 시간과 최대 자식 프로세스 RSS를 명시한다. RSS를 프로세스 트리 총 메모리로 표현하지 않는다. 전체 메모리/동시 실행은 별도 측정한다.
- 배포: 일반 사용자의 Rust 설치를 요구하지 않는다. 플랫폼별 바이너리 배포 검증 전 기본값을 전환하지 않는다.

## PR 경계

1. 기존 셸 개선 및 기준 측정: Rust와 독립적인 최적화·회귀 검사.
2. 검증 중 발견한 awk 감사 로그 보존 호환성 수정: 기존 awk에서도 동일한 보존 정책.
3. Rust 코어 및 차등 검증: 고정 빌드와 명시적 실험 선택, 실패 시 셸 복귀.
4. 재현 가능한 성능 측정 및 결과: 실제 수치와 한계, 채택/보류 판단.

통과해도 첫 채택은 선택형 실험이다. macOS/다른 CPU·배포 검증과 전체 출력 파이프라인 이전은 후속 단계다. 실패한 실험도 근거를 남기며, 성능만을 이유로 마스킹을 강화하거나 약화하지 않는다.
