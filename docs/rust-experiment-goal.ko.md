계획 단계에서 멈추지 않고 [PR #395](https://github.com/JeongJaeSoon/agent-guard/pull/395)에서

v3.7.0을 `e709445fb6fce9ade8cbbd2d6bcf2940e48da178`에서 실제 발행했다.

### v4 설계 후보와 호환성 변경 필요성 검토

v3.7 릴리스 커밋의 [실측 기록](rust-packaged-validation.ko.md)과 실제 공개 배포
검증을 바탕으로 검토했다. 이는 v4 구현·발행 완료 주장이 아니다.
현재 의도한 v4 호환성 변경 목록은 **없음**이다. 아래 병목만으로 기존 CLI나
정책을 깨야 한다는 근거가 성립하지 않는다.

| 영역 | 확인된 비용·유지보수 문제 | 다음 후보와 판정 기준 | 현재 결정 |
| --- | --- | --- | --- |

일부 대안은 실제 호환성 변경이 될 수 있지만 지금 채택할 이유가 없다. 셸/jq를
없애 최소 환경을 바꾸거나, 안정된 CLI 출력·종료 코드를 구조화된 새 형식으로
바꾸거나, 기존 설정·정규식 문법을 Rust 문법으로 치환하는 방안이 여기에 해당한다.
현재 관측된 병목은 내부 one-shot 처리 경계를 조정하는 호환적 접근으로 먼저
실험할 수 있다. 기존 기능을 제거해야만 얻는 이득이 입증되지 않았다.

상주 daemon도 당장 선택하지 않는다. 시작 비용을 줄일 가능성은 있지만 IPC 인증,
세션 분리, 비밀의 메모리 수명과 종료·업데이트 실패 경계를 새로 만든다. one-shot
개선으로 해결하기 어렵다는 측정 없이 운영 계약을 변경하지 않는다.

따라서 현재 변경 전후의 CLI 명령·옵션, 환경변수·설정, 출력 JSON/텍스트, 종료
코드, 설치 경로와 지원 환경에는 v4 차이가 없다. v3.7 사용자·설정·호스트 통합의
v4 마이그레이션도 필요하지 않다. Rust가 문제를 일으키면 기존 명시적
`AGENT_GUARD_EXPERIMENTAL_REDACTOR=shell`로 복구하고, standalone은 검증한
이전 버전 bootstrap, Homebrew는 해당 패키지 관리자의 버전 복구 경로를 사용한다.
호스트 marketplace의 태그 이동은 기존 공식 호스트 관리자 절차를 유지한다.

호환성 변경을 다시 제안할 때에는 위 영역별 측정, 호환적 대안의 실패 이유,
명령·설정·출력·종료 코드의 구체적 전후 예제, 자동/수동 이전과 되돌리기, 네 플랫폼
배포 및 호스트 검사를 함께 제출한다. 유지보수 개선은 단순 Rust 줄 수가 아니라
중복된 정책·파서 수, 같은 corpus의 재사용, 실제 수정 지점과 오류 경계의 감소로
판정한다. 버전 번호를 올리기 위한 변경과 v4.0.0 발행은 진행하지 않는다.

## 목표

**기존 마스킹 동작을 유지하면서 Rust 치환 코어와 개발·측정 도구의 Rust 이관을 검증하고, 성능 개선 PR을 main에 병합한 뒤 실제 릴리스를 발행한다. 발행 후 최신 main 기준으로 문서를 정리하고 모든 완료 근거를 남긴다.**

Python 개발 스크립트는 기능을 Rust로 옮기고 동등성을 검증한 뒤 제거한다.
성능 결과는 지연·CPU 시간·메모리·동시 처리량을 구분한 한국어 HTML 그래프로 정리한다.
마스킹이 과해지거나 약해지는 변경은 성능 개선으로 허용하지 않는다.

현재 Rust 범위는 문자열 치환 코어 `redact_tool_response_json`이다.
탐지·정책·호스트 처리는 여전히 셸이므로 이를 전체 Rust 재작성 완료로 표현하지 않는다.
v3.6.14 발행 당시 기본 동작은 셸/jq였다. Rust 기본 전환은 플랫폼별 사전 빌드
바이너리, Rust 미설치 환경의 설치·업데이트·실패 복귀를 검증한 뒤 위 후속
단계에서 별도로 판정한다. 내부 언어 변경만으로 v4를 자동 확정하지 않는다.

## 진행 순서와 완료 증거

1. 실행 환경을 복구하고 기존 작업 트리의 미커밋 Rust 이관 변경을 보존한다.
2. 개발 도구 이관을 검증한다. 기존 측정 입력·통계의 동등성을 확인하고,
   새 smoke 결과를 과거 성능 개선 수치와 섞지 않는다.
3. 커밋별 필수 CI를 확인해 관련 PR을 병합한다. 러너 종료와 코드 실패를 구분하며
   검사 생략·성공 상태 수동 입력으로 우회하지 않는다.
4. 기존 릴리스 절차와 정확한 SHA 검사 조건을 지켜 발행하고,
   실제 릴리스 URL과 배포 파일 체크섬을 확인한다.
5. 그 뒤 최신 main에 문서 정리를 반영한다. 원본 측정 근거는 유지하고
   오래된 검토·중복 로그·재생성 산출물만 정리한다.

## 사전에 정한 판정 기준

- 호환성: 독립 기대값 및 기존 jq와의 차등 검사에서 불일치 0. Unicode, 제어문자, 중복·겹침·연쇄 치환, 순서, 프로토콜 필드, 예산 경계를 포함한다.
- 오류: 잘못된 입력·실행 실패가 원문 유출이나 부분 출력으로 이어지지 않아야 한다. 바이너리 부재 시 정상 셸 경로로 복귀한다.
- 성능: 동일 Docker 이미지·스캐너·CPU/메모리 제한에서 교대 순서 반복 측정. 시작 비용을 포함한 코어와 실제 CLI를 모두 비교한다. 목표 경로 지연 또는 CPU 중앙값 10% 이상 개선, 일반 경로 5% 초과 회귀는 재측정·원인 분석 없이는 채택하지 않는다.
- 자원: CPU 시간과 최대 자식 프로세스 RSS를 명시한다. RSS를 프로세스 트리 총 메모리로 표현하지 않는다. 전체 메모리/동시 실행은 별도 측정한다.
- 배포: 일반 사용자의 Rust 설치를 요구하지 않는다. 플랫폼별 바이너리 배포 검증 전 기본값을 전환하지 않는다.

## PR 경계

1. 기존 셸 개선 및 기준 측정: Rust와 독립적인 최적화·회귀 검사.
2. 검증 중 발견한 awk 감사 로그 보존 호환성 수정: 기존 awk에서도 동일한 보존 정책.
3. jq 1.6 정상 문자열 과도 마스킹 수정: NUL 판정 및 구형 도구 CI.
4. Rust 코어 및 차등 검증: 고정 빌드와 명시적 실험 선택, 실패 시 셸 복귀.
5. 재현 가능한 성능 측정 및 결과: 실제 수치와 한계, 채택/보류 판단.

첫 채택은 선택형 실험이다. 측정 커밋의 Linux/macOS CI는 통과했으며, 다른 CPU·바이너리 배포 검증과 전체 출력 파이프라인 이전은 별도 단계다. 실패한 실험도 근거를 남기며, 성능만을 이유로 마스킹을 강화하거나 약화하지 않는다.

## 최종 비교 기준

초기 셸 기준에서 검증 중 발견한 두 호환성 수정을 양쪽에 동일하게 반영한
`16075762fa528f071f01f9c1998083b30aaca116`을 성능 비교 기준으로 사용한다.
Rust 후보의 CLI SHA-256은 `431e7c9ee678901e6c015ef36eb3e4b5195f162a4e55531aecaf68ac3992e622`다.
채택 기준의 10% 개선/5% 회귀 경계는 측정 전에 정한 값을 유지한다.

## 측정 환경 확인 후 기록한 제한

Docker는 rootless/cgroup driver `none`으로 동작하여 요청한 컨테이너별 2 CPU·1 GiB
제한이 적용되지 않았다. 실제 양쪽 실행은 같은 상위 4 CPU·16 GiB 한도를 공유한다.
판정의 10%/5% 경계는 그대로 유지한다. 상위 cgroup peak를 컨테이너 메모리로
사용하지 않고, 개별 자식 peak RSS와 10 ms 표본의 컨테이너 내부 프로세스 RSS 합을
구분해 보고한다. 후자는 공유 페이지 중복·순간 peak 누락 가능성이 있다.
엄격한 컨테이너별 제한 아래의 결과는 후속 검증 범위다.

## 측정 결과와 현재 판정

- Claude의 다수 문자열 치환: 지연 **27.3%**, CPU **26.3%** 감소.
- Codex의 같은 경로: 지연 **27.0%** 감소.
- 동시 작업 4개: 처리량 **40.3%** 증가, 표본 RSS 합 **3.7% 증가**. 메모리 절감은 입증되지 않았다.
- 일반 경로 지연 5% 초과 회귀: 측정 범위 내 없음. 초기 정상 입력의 변동은 별도 21쌍 재측정에서 **−0.8%**로 축소되었으며 Rust 효과로 주장하지 않는다.
- 차등 1,024건, jq 1.7.1/1.6 호스트·복귀 각 90건, 기존/Rust 출력 샤드 각 1,018건, 단위 201건, Rust 감사 로그 116건 통과.
- 측정 코어 커밋 `dd5b44d0134033f8ee5ef4c187e92aebcfb8214e`의 Rust 전용·legacy·plugin·HOL 및 Linux/macOS 전체 CI 통과. 이후 PR의 최신 커밋 CI는 별도로 확인한다.

성능 기준과 측정 코어의 CI는 통과해 **선택형 Rust 코어를 #380으로 main에 병합하고 v3.6.14를 발행했다. Rust 기본값 전환은 아직 완료되지 않았다.**
[그래프 HTML 보고서](rust-performance.ko.html)와 [원시 결과](../bench/results/rust-experiment/)에 근거를 남겼다.

## Rust 코어 이행과 기본값 판정

개발 도구 이관만으로 Rust 코어 이행 전체를 완료했다고 표시하지 않는다.
문자열 치환 코어는 #380으로 main에 들어갔고 차등·호스트·실패 복귀를 다시
확인한다. 탐지·정책·호스트 처리는 셸에 남아 있으므로 전체 재작성으로 부르지 않는다.

Rust 기본값 전환을 위해서는 Linux/macOS × x64/arm64 사전 빌드, 체크섬과
지원 시스템 라이브러리 확인, Rust 미설치 상태의 설치·업데이트·바이너리 부재·
실행 오류 복귀 검증이 필요하다. 이 증거가 없는 플랫폼에서는 기본값 전환을
보류한다. v3.6.14의 검증된 셸 배포와 선택형 코어를 구분해 릴리스 노트에 남긴다.
내부 언어 변경만으로 v4를 결정하지 않는다.
