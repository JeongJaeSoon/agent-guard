# 공통 정책 파일을 고정하는 별도 비교군

첫 성능 비교군은 gitleaks 설정을 v3.6.13의 같은 바이트로 고정했지만, 각 공개 배포본의 Bash 거부 정책 파일은 그대로 사용했다. 후속 파일 접근 검증에서 `hook_dependencies_ready`도 이 파일의 첫 활성 줄을 읽고, 그 파일의 SHA-256이 버전 사이에 달라졌음을 확인했다. 따라서 이 첫 비교군을 모든 정책 바이트가 동일한 통제 실험이라고 부르지 않는다.

기존 실행과 원시 자료는 버전별 공개 Bash 정책을 유지한 비교군으로 보존한다. 이미 진행 중인 실행은 취소하지 않는다. 그 숫자를 새 비교군과 합치거나, 새 조건의 표본으로 대신 사용하지 않는다.

사용자가 요구한 동일 설정 조건을 충족하기 위해 **새로운 전체 비교군을 실행하기 전** 다음 보충 조건을 고정한다.

- 공개 CLI·native helper·scanner 바이트는 기존과 동일한 고정 자산을 사용한다. 제품 파일은 수정하지 않는다.
- 모든 버전의 gitleaks 설정과 Bash 거부 정책은 v3.6.13의 파일로 명시적으로 고정한다(`--policy-mode common`).
- 읽기 거부 정책은 일곱 공개 배포본의 파일 해시가 같음을 검증한다. 별도 override가 제품의 사용자 설정 경로를 바꿀 수 있어 동일한 공개 기본 파일을 그대로 사용한다.
- 각 버전에서 실제 선택될 세 정책 파일의 경로·SHA-256 검증 자료를 **타이밍 전에** 보존한다. 검사에 실패하면 비교를 시작하지 않는다.
- 입력, 워밍업, 실행 방식, 타임아웃, 개선 10% 이상·회귀 5% 초과 기준은 바꾸지 않는다. 기본 버전 비교와 직접·선택형 비교는 기존 14회, 4동시 처리량과 전체 버전 RSS 비교는 기존에 고정한 16회 균형 순서를 사용한다.
- CLI 시간·CPU 계측과 표본 RSS 합 및 상세 trace 계측은 계속 분리한다.
- 새 비교군은 scanner×host별 새 runner를 사용하며 환경을 `linux-ci-controlled-…-2cpu-1g`로 구분한다. 실제 cgroup의 2 CPU quota·1 GiB·swap 사용 금지 값을 검사한다. 이전 runner와 CPU 모델이 다를 수 있으므로 이전 수치와 섞지 않는다.
- 설치와 공개 기본 정책의 정확도 검사는 이미 별도로 수행했으므로 다시 실행하지 않는다. 새 성능 비교군에서도 각 호출의 출력·상태를 같은 독립 기대값으로 검증하고 실패를 보존한다.

새 실행은 `Public version common-policy benchmark` 워크플로의 명시적 `public-version-controlled` 라벨 또는 수동 dispatch로 시작한다. `runtime/ci.sh LAB EVIDENCE IMAGE SCANNER HOST controlled`는 `run.py --policy-mode common --rss-all-versions --require-limits`를 호출한다.

이 변경은 결과가 좋지 않아 표본을 다시 고르는 조치가 아니다. 정책 파일의 숨은 버전 차이를 확인하여, 사용자가 처음 요청한 통제 조건을 별도 비교군에서 만족시키는 방법론 보완이다. 기존 실패와 기존 완료 표본은 원래 조건의 자료로 그대로 남긴다.
